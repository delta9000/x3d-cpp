# x3d-cpp SDK — v1 capability matrix

What the v1 façade (`x3d::sdk`) supports, and what is deferred to post-v1. The
deferred rows are breadth, not spine: the architecture accommodates each as an
isolated addition. Source of record: `docs/superpowers/specs/2026-06-16-v1-closure-roadmap-design.md`.
Behavioral / spec-conformance gaps are tracked in
[`docs/conformance/findings.yaml`](../conformance/findings.yaml); other deferrals are
GitHub issues.

The render-feed surface is experimental; see the
[native host contract](../wiki/guides/native-host.md) for ownership, mutation,
resource and identity limits. The installed-package host test is not Vulkan or
CAVEOS validation.

## In v1 (supported)

| Capability | Notes |
|---|---|
| Load 4 encodings (XML, ClassicVRML, VRML97, JSON) | + gzip input, lenient read, BOM strip. Parses versions 3.0–4.1; the generated node model targets 4.0, so the six 4.1-only nodes are absent (row below) |
| PROTO / EXTERNPROTO | Local declaration expansion and file-local EXTERNPROTO via `localFileProtoResolver` (http/urn skipped by default). Declaration-owned node defaults and nested literal overrides are cloned per instance; explicit caller node overrides retain sharing, and NULL/empty overrides suppress defaults. Readers isolate declaration DEF scopes and select nearer nested declarations across PROTO/EXTERNPROTO kinds. Direct body declaration order survives serialization, and expansion selects the first authored node/instance while retaining later nodes as active peers. Body-node declaration and child order is retained, including nested expansion and USE aliases. Contained declarations/instances in ordinary interface-default graphs are retained and expanded per outer instance. Direct ProtoInstance defaults retain order and DEF/USE identity through authored templates, materialized per outer instance before IS forwarding; node-valued fieldValues retain and expand direct and contained instances, preserving caller sharing and scene-root USE identity; unresolved caller templates remain inert and serializable. Scene roots and ordinary child fields preserve authored prototype positions through expansion and all four writers; unresolved templates retain their positions. Body-local nested ROUTEs and nested IS event connections resolve through declared interfaces to concrete targets, with alias, direction and type checks. Both scene ROUTE endpoints can use prototype interfaces. Declared scalar and node-valued interface fields without IS exist on the instance as real fields with their default/`fieldValue` initial value and routable endpoints: an unconnected `inputOutput` field acts as stored state that echoes a set value as its `_changed` event, `inputOnly` fields are route sinks and `outputOnly` fields route sources, for external routes and for an enclosing PROTO's body-local nested routes. Unconnected `SFNode`/`MFNode` defaults reuse per-instance clones; caller overrides and routed values preserve sharing, including NULL/empty values. This does not establish traversal of arbitrary dynamic node graphs; inherited metadata still uses primary-node storage. Classic/JSON writers reject unsupported repeated field/slot groups (PROTO-NESTED-WRITE). Expansion diagnostics are available through `protoWarnings`; this is not a complete PROTO conformance claim. |
| Inline / IMPORT | Parse-time Inline expansion; explicit child EXPORT required for IMPORT. With an injected `InlineResolver` and base URL, runtime `load` and `url` events load, unload, and replace content, including routes and IMPORT aliases; extraction deltas report added and removed items (ADR-0051). |
| Conformance diagnostics | `rangeWarnings` (out-of-range values) + `protoWarnings` (expansion issues); per-version validation moat |
| UNIT declarations | Parse-time validation requires X3D 3.3+, unique standard categories, names without whitespace, and finite positive factors. Valid declarations round-trip. Parsed Scenes and PROTO declarations retain source UNIT snapshots through Inline and EXTERNPROTO resolution, plus authored scalar-field presence through parsing and PROTO expansion. Runtime entry normalizes explicitly authored fields in its dimension table to initial units, including `TextureTransform.rotation` (angle); texture center/translation/scale remain dimensionless. Every length/angle field of the Interactive profile's nodes is mapped, including bounding boxes (the -1 -1 -1 sentinel is kept), PlaneSensor `axisRotation` and light `attenuation` (1/length, 1/length² terms). Generated defaults remain canonical, repeated initialization does not reconvert, and subsequent host/event writes use initial units. Fields of later components and conversion-aware serialization remain incomplete (REQ-UNIT); serialize before runtime entry to retain authored values. |
| Serialization | `XmlWriter` / `JsonWriter` / `VrmlWriter`, reflection-driven |
| Incremental geometry deltas | Shared direct content sources reach every geometry owner; dirty sources coalesce per owner per tick. Native AoS empty/nonempty transitions remove/add affected placements without rebuilding unrelated meshes. Consume deltas for live membership; `itemCount()` counts allocated slots. |
| Render-state deltas | `visible` changes active traversal; Shape descriptor fields (including `castShadow`), `ClipPlane`/`LocalFog` fields, and their indexed ancestor-frame changes conservatively replace the full baseline. Tracked-view changes to Billboard clip scopes are checked per placement. Apply removals before additions; item state and local-fog indices refresh together. Disabled/empty scopes retain dependencies; unrelated TRS remains incremental. This costs a bounded full re-extraction on affected ticks. |
| Scene graph | DEF/USE, Transform hierarchy (+ HAnimHumanoid/HAnimJoint/CADPart), bounds, binding stacks |
| View-dependent nodes | LOD, Billboard, ProximitySensor, VisibilitySensor. Render deltas track per-placement LOD selection and Billboard orientation under tracked-head and ancestor motion |
| Animation | TimeSensor, full interpolator family, Followers (§39 Damper + Chaser, all 14 node types), ROUTE cascade (§4.4.2.2 `set_`/`_changed` aliases accepted) |
| Custom behavior | subclass `System`, `ctx.addSystem`, dirty-aware `ctx.writeField` |
| Input seam | `setPointer` / `setPointerButton` / `setPointerPresent` / `setPointerScreen` / `setKey`, key-device `push*` events; `SessionOptions::anchorHandler` receives non-`#Viewpoint` Anchor activations |
| Pointing-device sensors | TouchSensor, PlaneSensor, CylinderSensor, SphereSensor (drag); CylinderSensor rotation is right-handed about +Y (IACC-1) |
| Navigation | EXAMINE, FLY, WALK, LOOKAT, NONE; avatar collision (Collision node: enabled, proxy, isActive/collideTime), WALK gravity and terrain following with step height |
| Picking engine | ray cast + closest hit; exact for Sphere/Box/Cone/Cylinder + indexed/triangle meshes; AABB proxy for the long tail |
| Extraction → render feed | full snapshot + incremental delta; GeomId distinguishes baked/deformed payload variants as well as revisions; optional AoS/packed origin-distance visibility hints refreshed by replacement only when a live hint changes (not bounds/frustum culling); meshes, materials, lights (scoped), fog (bound global `Fog` + per-placement scoped `LocalFog`, §24.4.3; experimental `LocalFogDesc::scopePath` distinguishes USE-shared enclosing groups), camera, background (gradient, the six panorama faces of Background/TextureBackground as TextureRefs, transparency), scene bounds; ComposedCubeMapTexture surfaces as a six-face cube ref (no bundled renderer samples cube maps yet) |
| Mesh primitives + sets | Box/Sphere/Cone/Cylinder, IFS/ITS/TriangleSet/strip/fan, ElevationGrid, Extrusion, IndexedLineSet/LineSet/PointSet, the 8 §14 2D primitives (Arc2D/ArcClose2D/Circle2D/Disk2D/Polyline2D/Polypoint2D/Rectangle2D/TriangleSet2D, XY plane). ElevationGrid/GeoElevationGrid honour authored `color`/`normal` + `colorPerVertex`/`normalPerVertex` (EXT-001 closed); Extrusion degenerate-spine SCP axes are pinned per ADR-0031 (EXTRUSION-SCP closed). |
| NURBS curves, patches, swept/swung surfaces + interpolators | `NurbsCurve` → line mesh; `NurbsPatchSurface`, `NurbsSweptSurface`, `NurbsSwungSurface` → triangle mesh with analytic/central-difference normals; plus the three §27 interpolators (curve positions, tangent orientations, surface positions/normals), via shared first-party `runtime/extract/NurbsEval.hpp` math (ADR-0040; NRB-1/NRB-2 closed, NRB-3 swept/swung). **Caveat:** `NurbsTrimmedSurface` (needs 2D contour clipping/triangulation) and authored `NurbsTextureCoordinate` remain deferred (NRB-3); deferred geometry uses the `externalGeometryResolver` fallback |
| Normals | flat + creaseAngle smoothing (lattice-adjacency) |
| Texture coordinates | default per-primitive (§13), authored TextureCoordinate(Generator), TextureTransform. TextureTransform order fixed to the §18.4.10 matrix (TXF-1 closed); the CPU reference host implements all eleven Table 18.6 modes for unlit, Phong and PBR; the OpenGL PoC evaluates all eleven per fragment with the generated-coordinate TextureTransform (TXF-2 fixed), one generator per material (REQ-MULTITEXTURE-2) |
| Texture descriptors | `TextureRef` (url/repeat/sampler/texCoordMapping multi-UV) + §18.4.9 `extSampler` (boundary modes S/T/R, magnification/minification filters, mipmaps, anisotropy), resolved RGBA via the `TextureResolver` seam; ORM channel-packing documented (MAT-007, MAT-008); the CPU reference sampler implements all boundary modes, magnification/minification filters, generated mipmaps and anisotropy up to 16 (TXF-4). 3D textures (T3D-1): `PixelTexture3D` (inline `Texture3DDesc` voxels) and `ComposedTexture3D` (2D slice refs) surface as `TextureRef::Source::Tex3D` with `repeatR`; `ImageTexture3D` and 3D sampling remain ignored (white fallback) |
| 3D textures (§33) | **Partial (T3D-1).** `PixelTexture3D` and `ComposedTexture3D` extract a `Source::Tex3D` descriptor (dimensions, component count, texel bytes / slice refs, `repeatR`); `ImageTexture3D` is unhandled (no 3D image decoder shipped); no bundled renderer samples 3D textures — `cpu_raster`/`poc_renderer` fall back to the flat material color. |
| Material descriptors | `MaterialDesc` discriminated union: Phong (`Material`) / Physical (`PhysicalMaterial`) / Unlit (`UnlitMaterial`); `MaterialModel` tag; `backMaterial` (unique_ptr, two-sided, MAT-006); `doubleSided`; `toRGBA()`; gamma/sRGB stance documented (MAT-009) |
| Polygon fill and hatching | `MaterialDesc::fill` carries `FillProperties`; live edits and replacement update extraction. CPU and built-in OpenGL shaders implement independent filled/hatched flags, hatch color, styles 1–6 and fallback to style 1. Polygon holes leave depth untouched; lines and points are unaffected. |
| Clip planes (§11.4.1) | `SceneExtractor` collects enabled `ClipPlane` nodes as scoped state (affecting the following siblings and their subtrees within the parent grouping node) and carries them on `RenderItem::clipPlanes` (`ClipPlaneList`, fixed capacity 6 per Annex F.5) resolved to world space. The CPU reference rasterizer discards fragments in the clipped half-space. The OpenGL `poc_renderer` maps the planes to eye space and clips every built-in program with `gl_ClipDistance`; author programs receive them as the `numClipPlanes`/`clipPlane[]` vocabulary uniforms and clip themselves. |
| Author shaders (§31) | `selectShader()` picks each Appearance's first valid GLSL `ComposedShader`/`ProgramShader` (`PackagedShader` and other languages stay inert); `RenderItem::shaderProgram` carries the resolved stage sources (CDATA, `data:` urls or `ShaderOptions::resolver`) and the author fields' current SF values. `ShaderSystem` emits `isSelected`/`isValid` and handles `activate`; validity is the host's `ShaderOptions::validator` (default: a VERTEX and a FRAGMENT part). Uniform events and source edits arrive as `updatedMaterial`. `ShaderUniformVocabulary` + `buildBindingPlan()` classify uniform names. Ignored: SFNode texture and MF array uniforms carry no value (REQ-SHADER-2). |
| Text | FontMetrics seam + layout engine (justify/spacing/length/maxExtent) + glyph render-items + Text output fields. Optional stbtt atlas covers printable Basic Latin U+0020–U+007E and Latin-1 Supplement U+00A0–U+00FF present in the supplied font, with complete bitmap-aligned glyph boxes; other codepoints fail and styles use the supplied PLAIN face. This does not imply general Unicode shaping support; the CPU consumer’s separate built-in font remains ASCII-only. **Caveat:** `justify` END mis-aligns the minor axis for `topToBottom=FALSE` (horizontal) and `leftToRight=FALSE` (vertical) — TXT-2/TXT-4 |
| Scripting / SAI | ECMAScript via Duktape, in-process SAI core; `ScriptEngine` / `ScriptSystem` / `SaiContext`. **File-authored Scripts supported across all 4 encodings** (XML `<field>`+CDATA, ClassicVRML/VRML97 interface decls + `url` body, JSON field array + source): author fields land in the scene-owned `DynamicFieldStore` (visible via explicit `effectiveFields(node, store)` to ROUTE + SAI resolution), inline source captured into `Script.sourceCode`, handlers dispatch, author `outputOnly`/`inputOutput` writes drive the cascade (SCR-SAI-DYN S1) |
| Native author-field ownership | Fresh Scenes have independent stores; shallow copies deliberately alias graph and store. Declarations retain template state, clones get fresh entries, and retained Inline/GeoLOD child state survives parent detachment. Script backends and writers receive explicit owners; no global store or fallback clone factory remains. Concrete runtime/source migration requires a rebuild. See [ADR-0057](../wiki/decisions/0057-scene-owned-author-fields.md). This is not full Script/PROTO/SAI conformance. |
| Native runtime lifetime | `RuntimeSession` and low-level `X3DExecutionContext` retire guarded native runtime callbacks before owned state is destroyed. Retained node storage is safe to read and its retired input handlers are inert; construction failure and replacement are covered. Standalone binding/standard behavior owners revoke in their destructor bodies before member captures can reenter. Custom most-derived owners must call the early-retirement hook. Hosts serialize each world’s calls and defer teardown until no native call/callback is in flight. Pick/local-matrix diagnostic totals remain process-wide and use relaxed atomic counters for separate owner-thread worlds. Context, binding-system and behavior-system owners are noncopyable/nonmovable; transfer owning pointers or build fresh owners. See [activation ownership and retirement](../wiki/subsystems/execution-context.md#activation-ownership-and-retirement). |
| Paired synchronous asset loaders | `AssetResolver` Inline/EXTERNPROTO loaders preserve the same I/O policy recursively, retain fetched-source bases through declaration caching/body expansion and IS URL overrides, and never restore local-file fallback. `Pending` aborts the recursive synchronous load. Local Inline loading applies the existing confinement/canonicalization helper. Evidence: `asset_loader_policy_test.cpp` and `asset_proto_resolver_test.cpp`; see [parse readers](../wiki/subsystems/parse-readers.md). |
| Asset resolver / IO seam | `AssetResolver` (`function<AssetResult(url, AssetKind)>`) — header-only std-function callback with two invocation contracts (render-time Pending-allowed + parse-time SYNC); proven generic via libcurl HTTP + AWS S3 SDK backends (ADR-0023, [seam-status GREEN](../wiki/seam-status.md)). Embedder opts in via `-DX3D_CPP_BUILD_CURL=ON` and/or `-DX3D_CPP_BUILD_S3=ON`; default build (both OFF) keeps the bytes-not-loaded-here invariant |
| H-Anim (§26) | Skin deformation through `RenderItem::SkinDesc` + `RenderDelta::updatedSkinPose` (GPU palette) or `SceneExtractor::deformedMesh` (reference CPU skinner); Joint and Segment displacers; HAnimMotion playback (ADR-0055). Not wired: IK limits/stiffness, `skeletalConfiguration`, `loa`, mass properties. |
| Geospatial projection ownership | Context/session retains a constructor-fixed const backend, with an immutable built-in default. Meshes, bounds, picking, camera and geospatial behavior use that same owner. The removed process-global selector and newly explicit helper parameters require source migration and a rebuild; the mathematical virtual interface is unchanged. See [ADR-0058](../wiki/decisions/0058-context-owned-geo-projection.md). This does not establish complete Geospatial/SAI support. |
| Sound / Audio (§16) — **seam in v1; §16 node coverage partial** | The engine-agnostic `AudioBackend` seam + dependency-free `BuiltinDspBackend` ship; MiniaudioBackend is optional and its swap test requires the external dependency. The Immersive-profile pair is built: `Sound` and `AudioClip` (asset resolver/decoder, `MediaTimeSystem` lifecycle; ADR-0050), plus `BufferAudioSource` (authored PCM `buffer` through the same Buffer node; mono after averaging multi-channel buffers, `bufferDuration` truncation, loop via the lifecycle, `playbackRate`×`detune` captured at activation; `loopStart`/`loopEnd`/`url`/`length` not wired — SND-4). Wired v4 nodes use the shared time-dependent lifecycle via `SoundTimeSystem`; `AudioDestination.gain` scales output (SND-2/7). Both backends honor `enabled` on all wired source/processing nodes, including a disabled BiquadFilter passing its input through (SND-1). `Delay` (§16.4.6) and `DynamicsCompressor` (§16.4.9) are built on `BuiltinDspBackend` only (ring-buffer delay with `delayTime` clamped to `[0, maxDelayTime]`; feed-forward soft-knee compressor whose `reduction` output is not reported, since the seam has no per-node metering path; `WaveShaper` (§16.4.21) is built the same way — linear-interpolated `curve`, `oversample` NONE-only, `curve` supplied by the UOM-SND-1 errata overlay; SND-5). `maxChannelCount` remains unused by mono rendering and `StreamAudioDestination` remains unbuilt. Analyser/Convolver and `StreamAudioSource`/`MicrophoneSource` are skipped (SND-4/5); `tailTime` and HRTF/Doppler remain deferred (SND-3/8), and a `PeriodicWave` is realized only when registered via `SoundSystem::setPeriodicWave` (built-in-backend synthesis; MiniaudioBackend falls back to sine) because the authored `OscillatorSource.periodicWave` field is X3D 4.1 and the generated bindings model 4.0 (SND-9). See `docs/conformance/components/Sound.md`. |
| Movie decode seam | `MovieDecoder` — **STABLE**, proven generic via two backends: pl_mpeg / MPEG-1 (`-DX3D_CPP_BUILD_PLMPEG=ON`) and libtheora / Ogg-Theora (`-DX3D_CPP_BUILD_THEORA=ON`), CI-gated by `x3d_movie_tests` (ADR-0041, [seam-status](../wiki/seam-status.md)). The callback is owned by the **consumer**: the SDK never invokes it and never opens a media file or links a codec. MovieTexture *frame playback* is a separate, deferred concern — see the post-v1 table below |
| Rigid-body physics (§37) | engine-agnostic core seam + flag-gated Jolt backend (`-DX3D_CPP_BUILD_PHYSICS=ON`, Jolt v5.5.0; ADR-0019): RigidBodyCollection over Box/Sphere/Cylinder/Cone + gravity + forces/torques/damping + auto-disable sleeping (`autoDisable`/`disableTime`/`disableLinearSpeed`; `disableAngularSpeed` and per-body thresholds ignored — Jolt's sleep tuning is world-wide) + collision response + CollisionSensor reporting (contacts/intersections/isActive) + Ball/Hinge/Slider joints, plus collection solver tuning (`iterations`/`errorCorrection`/`contactSurfaceThickness`/`maxCorrectionSpeed` → Jolt solver settings; applied only off the §37 default). Remaining §37 fields/nodes ignored (see [physics.md](../wiki/subsystems/physics.md) §37 matrix + `CONF-RBP*`) |
| Authoring / Export pipeline | `x3d_cpp::authoring` slim header target (nodes, document model, XML/JSON/VRML codecs, range validation, profile fit). Footprint gate (`authoring-footprint.sh`) enforces symbol quarantine. CLI `x3d_asset_import` converts 3D assets to conformant X3D 4.0 with deduplicated, recompressed textures in `assets/`. Backends resolve through a priority `BackendRegistry` (`--backend` override); **glTF is first-class via the default-ON header-only cgltf backend** (no assimp required), with assimp as the broader-format fallback and USD/USDZ opt-in — the `ImportSource` seam's genericity proven by a cgltf-vs-assimp swap-test (ADR-0044). |


## Post-v1 (deferred, with reasons)

Not exposed in the façade — not even as experimental. These are scene-dependent
breadth. Each is tracked as a card in the
[GitHub Project](https://github.com/users/delta9000/projects/2).

| Deferred | Reason |
|---|---|
| EXPLORE mode; ANIMATE transition curve; MPEG-object LOOKAT | Not in the Core/Interchange minimum; spline curve + media-object seam have no corpus coverage. |
| Pick-sensor nodes (Line/Point/Primitive/VolumePickSensor) | Read `pickingGeometry`/`pickTarget`, distinct from the pointer-device seam; no current consumer (the pick *engine* ships). |
| Full / dynamic SAI (`createX3DFromString`, runtime node add/remove) | Dynamic structural mutation needs incremental re-indexing; no current consumer. |
| NURBS trimmed surface | Curve + patch, swept/swung surfaces, and interpolators ship in v1 (see *In v1*, ADR-0040, NRB-1/NRB-2/NRB-3). The remaining NURBS node is `NurbsTrimmedSurface`, which needs 2D contour-loop point-in-region clipping + polygon triangulation in the `(u,v)` domain (no such helper exists — NRB-3); authored `NurbsTextureCoordinate` is also deferred. Lowest-impact corpus slice. |
| Geospatial (full projection) | Geo coordinates and GeoLOD URL tiles use the projection and runtime Inline resolver; applications supply URL resolution and an optional geoid model. |
| Layering / Layout (per-layer binding + view volumes) | Needs binding stacks + view-dependent eval keyed by layer. |
| Particle systems | Advanced component; breadth beyond the common-scene v1 target. (Rigid-body physics and audio ship as seams — see *In v1*.) |
| The six X3D 4.1-only nodes (incl. `EnvironmentLight` / IBL) | `generated_cpp_bindings/` is code-generated from the **4.0** UOM under a byte-identical golden invariant, so a hand-authored 4.1 binding would conflict with the golden gate. All six nodes 4.1 adds over 4.0 are therefore absent: `EnvironmentLight`, `FontLibrary`, `HAnimPose`, `InlineGeometry`, `RenderedTexture`, `Tangent`. A 4.1 document still parses and runs — only these node types are missing. Needs a defined strategy for 4.1 extension nodes; for `EnvironmentLight` specifically the `ShaderUniformVocabulary` already reserves `envDiffuse`/`envSpecular`/`envSH`/`brdfLUT`. |
| MultiTexture compositing, MovieTexture frames | CPU reference host implements all MultiTexture modes, source/function controls, RGB/alpha mode tokens and per-stage mapped/generated/transformed UVs (REQ-MULTITEXTURE). The published REPLACE/SELECTARG2 contradictions have explicit tested interpretations. The GL PoC combines up to four stages over four UV sets with the same operators (REQ-MULTITEXTURE-2 records its limits). |
| MovieTexture frames | Beyond the single-channel `TextureRef` descriptor. |
| Bidi / complex text shaping (language field) | Beyond left-to-right / top-to-bottom layout. |

## Known v1 limitations (work, with caveats)

| Limitation | Impact |
|---|---|
| `worldTransform(node)` / per-item path keying uses the first path | A node reached through a USE'd interior group reports its first-path transform. |
| VisibilitySensor uses a forward cone, not a 6-plane frustum | Conservative (over-reports visible, never wrongly culls); consumers can supply planes. |
| `MaterialDesc::textures[]` is descriptor-only in the first PoC | Populated but the SDK does not itself consume it; the consumer binds. |
| `RenderDelta` unsupported-geometry push channel not wired | Use the `skippedGeometryCounts()` pull accessor instead. |
| Per-light shadows | CPU reference host applies triangle occlusion, `shadows`, `shadowIntensity`, `castShadow` and visibility, with scale-normalized ray queries. The GL PoC remains unobstructed (REQ-SHADOW). |
| `FogCoordinate` per-vertex depths are ignored | `MeshBuilder` never reads a geometry's `fogCoord` and `MeshData` carries no fog-depth array, so authored depths do not replace the computed eye-space distance. Reference renderers fog by distance only. `LocalFog` scope IS wired (see the render feed above) and both reference renderers draw it. |

## Interchange reference host

`mise run interchange` builds the headless CPU consumer with stb PNG/JPEG decode
and file/HTTP/FTP fetch routes. Its acceptance suite checks presentation and the
Annex B geometry, field, image, light and interpolation capacities alongside the
shared SDK gates. See the [current Interchange evidence](../wiki/guides/x3d4-requirements-audit.md#interchange-reference-host-acceptance-2026-10-02)
for configuration, implementation choices and scope. The SDK core and OpenGL PoC
do not independently inherit this host claim.

## Interactive reference host

`RuntimeSession` with `SessionOptions::interactive` is the Annex C host: XML
scenes driven only through the pointer, key and bind seams. Its acceptance
suite (`runtime/extract/tests/interactive_profile_test.cpp`, part of `mise run
ci`) covers the pointing, key-device and environmental sensors, viewpoint
binding and transitions, EXAMINE/FLY/LOOKAT navigation, event utilities and
Anchor activation. See the [Interactive evidence](../wiki/guides/x3d4-requirements-audit.md#interactive-reference-host-acceptance-2026-10-10)
for scope, the gaps it closed and recorded interpretations.
