## Findings

- **REQ-UNIT** [major/OPEN] — §4.3.6; 7.2.5.5: Runtime applies UNIT factors to explicitly authored known dimensional values at initialization; components beyond Interactive and conversion-aware writing remain incomplete.
  - Runtime entry normalizes explicitly authored known dimensional fields to initial/SI units, while generated built-in defaults remain canonical. Focused tests: `UNIT runtime: equivalent authored length and angle geometry`, `UNIT runtime: routed motion, defaults, and subsequent writes use initial units`, `UNIT runtime: Inline and EXTERNPROTO use their source units`, `UNIT runtime: PhysicsSystem receives kilograms and newtons`, and `UNIT runtime: custom PROTO values convert independently at dimensional IS targets`. TextureTransform.rotation now also converts authored angle units, including dimensional IS targets; two TextureTransform UNIT regressions retain dimensionless UV center/translation/scale, defaults, idempotent initialization and subsequent radian writes. Coverage demonstrates equivalent degree/radian geometry, routed updates, length, mass, force and torque, source-specific Inline/EXTERNPROTO factors, dimensional IS targets, and codec round-trip preservation before runtime. REQ-UNIT remains open: the field-dimension map and its range are incomplete, and serialization after runtime conversion does not yet preserve authoring units. Background and TextureBackground skyAngle/groundAngle now normalize authored angle units, with an idempotence regression. Every length/angle field of the Interactive profile's nodes is now mapped: X3DBoundedObject bboxCenter/bboxSize on every node (the -1 -1 -1 bboxSize sentinel is kept), PlaneSensor axisRotation, and PointLight/SpotLight attenuation, whose linear and quadratic coefficients scale by 1/length and 1/length^2 so falloff is equivalent at the same physical distance (`UNIT runtime: Interactive-profile bounds, sensor and light fields`). Still open: fields of components beyond Interactive that are not in the map (for example TextureCoordinateGenerator SPHERE-REFLECT-LOCAL eye parameters) and serialization in authoring units after runtime conversion. Resolve the published Core wording on external UNIT declarations separately from the demonstrated runtime behavior.
- **PROTO-NESTED-WRITE** [major/OPEN] — §4.4.4.4: Some cross-encoding declaration orders remain unsupported.
  - Remaining: Classic repeated field groups with intervening other fields or prefixes containing prototype instances/declarations (including descendants/default templates and author fields), and JSON repeated slot groups. They still fail explicitly; supporting them needs binding-aware scope rewriting and cross-field ordering. Classic now moves intervening local/extern declarations before an ordinary node prefix of the same field, preserving child order, expansion and DEF/USE identity (literalPrefixDeclarationRoundTripTest). The declaration ledger is not mutated. Direct body order and XML/canonical XML node-child order already round-trip. Existing nodeContainedInterleavedFieldTest retains the shadowing rejection; repeatedNodeFieldJsonGuardTest retains the JSON duplicate-slot guard. JSON checks establish repository compatibility, not ISO encoding conformance.
