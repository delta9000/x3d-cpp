## Findings

- **REQ-PROJECTION** [minor/OPEN] — §42.2; 42.3.1; 42.4.1; 42.4.2: Both reference hosts light the scene through perspective and parallel texture projectors (ADR-0061); projector shadows, MultiTexture projector textures, author shaders and the aspectRatio output for url images are not wired.
  - Texture projectors (2026-10-11, ADR-0061): SceneExtractor::projectors() returns a world-resolved ProjectorDesc per active TextureProjector/TextureProjectorParallel (LightSystem::collectProjectors, same Switch/LOD selection and per-path transforms as lights; on FALSE skipped). It carries color, intensity, ambientIntensity, location, direction, the up vector (perspective upVector, parallel +Y; falls back to +Y then +Z when parallel to direction), near/far and parallel extents scaled by the local frame, fieldOfView (covering the shorter image side), aspectRatio from the resolved image, view/projection matrices, the texture as a TextureRef resolved through the session TextureResolver, and global/scopeRoot (projectorApplies). ProjectorDesc::project() maps a world point to (s, t) or rejects it outside the volume, behind the projector, or outside nearDistance/farDistance. Both hosts treat a projector as a light without attenuation (perspective: positional at location; parallel: directional) whose colour is filtered by the projected texel rgb x alpha inside the volume and is zero outside, in Phong and PBR (cpu_raster MaterialShader EyeLight::projected; GL PoC shaders/projector.glsl, up to 3 projectors on units 13-15 sharing the 8 light slots after ordinary lights). The spec does not define how the projected texture combines with lighting (§17 has no projector term), so that combination is an implementation choice. TextureProjectorSystem (attachStandardRuntime) emits aspectRatio for PixelTexture textures on load and when the texture or its image changes. Not wired: shadows and shadowIntensity (carried in ProjectorDesc, not rendered), MultiTexture as a projector texture (no texture), projectors in author shaders, aspectRatio output for url textures (the runtime does not decode images; ProjectorDesc.aspectRatio has the resolved value), and in the GL PoC more than 3 projectors or more than the light slots left after ordinary lights. Tests: texture_projector_test (doctest: volume, coordinates, range, local scale, scope, up fallback, url aspect, aspectRatio output), texture_projector_test (cpu_raster) and texture_projector_gl_test.py (perspective and parallel quadrants in Phong and PBR, scope, nearDistance). Acceptance for the rest: projector shadows, MultiTexture textures, author-shader access, url aspectRatio output.
- **TPJ-1** [minor/CLOSED] — §42.4.2: Not a bug: 'shadowsIntensity' is an X3D 4.1 prose typo; code/UOM correctly use 'shadowIntensity'.
  - RESOLVED as erratum — field name in code is correct. CONFIRMED against the published ISO/IEC 19775-1:2023 normative text (web3d IS HTML; ISO PDF is paywalled, the IS HTML is the authoritative free form): TextureProjectorParallel §42.4.2 genuinely declares 'SFFloat [in,out] shadowsIntensity 1 [0,1]' (trailing s) in both the node grammar and the field summary — so it is in the actual standard, not a mirror artifact. It is nonetheless a spec erratum: shadowIntensity is the inherited X3DLightNode field, spelled singular on X3DLightNode, DirectionalLight, SpotLight, and the sibling TextureProjector; an inherited field cannot be renamed on one subclass, and DirectionalLight (the canonical parallel-ray light) uses the singular, so 'parallel => plural' has no basis. Web3d's own UOM normalizes to shadowIntensity; the generator emits the correct name. NO rename. Tolerant-alias follow-up split out as TPJ-2. (sweep 2026-06-25; PDF/published-spec verified 2026-06-25)
