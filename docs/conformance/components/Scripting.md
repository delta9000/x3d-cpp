## Findings

- **REQ-JAVA** [major/DEFERRED] — §F.5 Table F.3 (Script); 29.2.8; 29.4.1: The published Full profile requires Java scripting in addition to ECMAScript; the shipped engines implement ECMAScript only.
  - EcmaScriptBackend and QuickJsBackend are the two concrete ScriptEngine implementations. An external engine could fill this seam, but no Java adapter or language-selection configuration is supplied or tested. The component's general allowance to choose languages must be read with the Full-profile requirement. Acceptance: a declared Full host runs Java Script fixtures with the applicable SAI binding and ordered URL fallback; this does not require adding a JVM dependency to the default SDK.
- **SCRIPT-BROWSER-SERVICES** [major/OPEN] — §29.2.4; ISO/IEC 19777-1 clause 6 (Browser object); ISO/IEC 19775-2 6.3: The script `Browser` object offers only getName, getVersion, print/println, addRoute, deleteRoute, currentTime and currentFrameRate. createX3DFromString, createVrmlFromString, createX3DFromURL, loadURL, replaceWorld, currentScene, createNode and the property forms (name, version, currentSpeed) are missing, so a script that builds scene content fails with 'not callable'.
  - Needs a parse-and-attach path through SaiContext under the directOutput gate. Planned with the SAI convergence work.
- **NATIVE-AUTHOR-FIELD-OWNERSHIP** [critical/FIXED] — §4.4.4; 9.2; 29.2 (native ownership and host integration): Scene and declaration owners replace process-global author-field storage and clone factory configuration.
  - scene_author_field_ownership_test.cpp: Fresh scenes own separate author stores while deliberate graph copies and retained children preserve their intended entry identities.
- **LIFE-STRUCTURAL-DETACH** [major/FIXED] — §ISO/IEC 19775-1 §4.4.3, §10.2.1: Structural field writes detach unreachable systems before releasing nodes and attach newly reachable subtrees.
  - Shared nodes remain attached through their other parents. Cascade and direct writes retain replaced node values through lifecycle reconciliation, using the same subtree collector as Inline retirement. System detach waits for active cascade callbacks to return; retained nodes keep their author fields for reattachment. Tests: x3d_structural_lifetime and runtime_callback_retirement_test.cpp structural Script cases.
- **LIFE-SCRIPT-RETIRE** [major/FIXED] — §ISO/IEC 19775-1 §29.2.3: Context retirement shuts down scripts while context state is alive and revokes retained SAI bridges.
  - Script handles are invalidated even when the host retains ScriptSystem. Shutdown may perform self and directOutput writes before callback retirement. A copied SaiContext rejects access after retirement. Tests: runtime_callback_retirement_test.cpp context teardown and shutdown-write cases.
- **DELTA-DIRECTOUTPUT-AUTHOR** [major/FIXED] — §ISO/IEC 19775-1 §29.2.6, §31.2.4: Script directOutput writes to shader author fields notify dirty tracking and update extracted uniforms.
  - SaiContext uses the dirty-aware execution-context write for static and author fields, retaining direct value mutation semantics. Type-mismatched author writes leave values and dirtiness unchanged. Tests: shader_selection_test.cpp directOutput author uniform writes reach the render delta.
- **SCR-001** [major/FIXED] — §29.2.5: prepareEvents() called exactly once per timestamp before ROUTE processing.
  - SCR-* are behavioral claims about the ScriptEngine seam, not Duktape-specific; the x3d_quickjs_swap test re-verifies they hold identically under the second (QuickJS) backend — SCR conformance is backend-independent. See ADR-0022 / docs/wiki/seam-status.md.
- **SCR-002** [major/FIXED] — §29.2.3: shutdown() invoked on world unload (~ScriptSystem teardown).
- **SCR-003** [major/FIXED] — §29.2.4: eventsProcessed() JS-global outputs read back into the cascade.
- **SCR-004** [major/FIXED] — §29.2.5: prepareEvents() JS-global outputs read back into the cascade.
- **SCR-006** [major/FIXED] — §29.2.2, 19777-1: SFMatrix3f/4f(+d) author fields marshal to/from ECMAScript.
- **CONF-CRITIC-2** [major/CLOSED] — §29.3.1: Script external-URL (@url in source) loading + auto-refresh interaction unimplemented.
  - Closed 2026-09-26: ScriptSystem::resolveSource() fetches external (non-ecmascript:/javascript:) url entries through the injectable extract::AssetResolver (Ready=source, Pending=retry next tick, Failed=advance to the next url), and update() retries Pending fetches once per tick. Default resolver is the IO-free null stub; the CLI injects io::file::makeFileResolver (sim_runtime.hpp). Tested in x3d_script_system (testExternalUrlFetch).
- **DO-CASCADE** [major/CLOSED] — §29.2.6, 4.4.8.3: directOutput cross-node write is injected as a routable cascade seed (19775-1 29.2.6) instead of a non-routable value mutation (SAI 19775-2 4.5.2).
  - sai_context_test.cpp: Direct output writes mutate native state without generating a routed field event under the recorded SAI interpretation.
- **SCRIPT-EVENTIN** [major/FIXED] — §29.2; 4.4.8.3: A ROUTE into a Script inputOnly field now runs the script function of the same name, and a routed inputOutput value reaches the script's variable; before, both stopped in the author-field store and needed embedder wiring.
  - cascade_author_field_test.cpp: Routed author fields reach Script handlers through the explicit author-field store.
- **SCRIPT-RUNAWAY-HANG** [major/FIXED] — §29.2.4 (ECMAScript binding 19777-1): A Script handler or top level that never returned hung the host; neither engine bounded script run time.
  - ScriptEngine::setCallBudget (default 2 s) bounds every entry into script code. Duktape uses its exec-timeout check (DUK_USE_EXEC_TIMEOUT_CHECK, local duk_config.h change) and QuickJS uses JS_SetInterruptHandler. An interrupted call is logged as a script error and the script stays loaded; a catch-and-continue loop cannot outlast it. ADR-0048 (amended). Tests: ecmascript/quickjs backend T15g.
- **SCRIPT-UNBOUNDED-MEMORY** [major/FIXED] — §29.2.4 (ECMAScript binding 19777-1): A Script could allocate without bound and get the host process killed; neither engine capped script memory.
  - ScriptEngine::setMemoryLimit (default 256 MiB). Duktape uses a counting allocator per script; QuickJS uses JS_SetMemoryLimit on its shared runtime, so there it caps the scripts' combined heap. Past the cap an allocation fails and becomes a contained out-of-memory error. ADR-0048 (amended). Tests: ecmascript/quickjs backend T15h.
- **SCRIPT-HOSTILE-VALUE-ABORT** [major/FIXED] — §29.2.4 (ECMAScript binding 19777-1): A Script whose author-field value threw while being read back crashed the host process under Duktape, and QuickJS emitted a half-read value.
  - The throw could come from a getter, toJSON, a Proxy trap, or a global or handler accessor. Readback ran outside any duk_pcall, so Duktape's fatal handler aborted the host. Duktape is now compiled as C++ with DUK_USE_CPP_EXCEPTIONS, and every engine entry runs under duk_safe_call. A throw drops that field's event and is logged. QuickJS readback now drops the field on a pending exception. ADR-0048 (amended). Tests: ecmascript/quickjs backend T15f.
- **SCRIPT-SFNODE-REFERENCE** [major/FIXED] — §29.2.4 (ECMAScript binding 19777-1: SFNode is a node reference): A script's SFNode was a raw pointer rebuilt as a non-owning shared_ptr — an SFNode written into a field could dangle, and under QuickJS a script could forge a handle to an arbitrary address.
  - ADR-0048. Handles are per-script NodeHandleTable ids (Duktape hidden symbol / QuickJS class opaque) that resolve to the node's owning shared_ptr, or to null for unknown ids and destroyed nodes. A script SFNode output shares ownership like DEF/USE. Tests: ecmascript/quickjs backend T15b-c.
- **JSON-TYPED-FIELD-VALUES** [major/FIXED] — §ISO/IEC 19776-5 5.1.3, 5.2, 5.6, 5.15, Annex A: JSON author fields, prototype defaults, and instance overrides retain native typed values.
  - The reader uses the declared field type to decode numbers, booleans, and arrays, and accepts legacy wire strings emitted by the existing writer. Test: reader_audit_test.cpp, JSON typed author and prototype field values are retained.
- **CLASSIC-SCRIPT-DECLARATION-IS** [major/FIXED] — §ISO/IEC 19776-2 A.3: Classic Script declaration IS syntax records author-field mappings on the enclosing prototype.
  - All four access types retain their connections, and expanded persistent fields receive the prototype values. The VRML97 reader shares this path. Test: reader_audit_test.cpp, Classic Script declaration IS retains author field connections.
- **CLASSIC-BARE-MFIMAGE** [major/FIXED] — §ISO/IEC 19776-2 5.1.2, 5.7: A bare single Classic MFImage value consumes the complete image header and pixel data.
  - The collector reuses SFImage collection for a bare MFImage element, including an empty image; subsequent fields remain intact. Test: reader_audit_test.cpp, Classic bare MFImage captures a complete single image.
- **SCRIPT-NODE-DEFAULT-CODECS-READ** [major/FIXED] — §ISO/IEC 19776-2 5.13, A.3; ISO/IEC 19776-5 5.13, Annex A: Classic and JSON readers retain author SFNode and MFNode defaults with DEF/USE identity.
  - Node-valued defaults stay in the author-field value graph, including direct and contained ProtoInstance templates, null SFNode values, and empty MFNode lists. Reader-side closure of SCRIPT-NODE-DEFAULT-CODECS; writer behavior is tracked separately. Test: reader_audit_test.cpp, Classic and JSON retain Script author node defaults and aliases.
- **PROTO-INSTANCE-IS-WRITE** [major/FIXED] — §ISO/IEC 19775-1, 4.8; ISO/IEC 19776-1, 4.3.8: All four writers retain IS mappings on nested prototype instances.

- **CANONICAL-MISSING-MF-TYPES** [major/FIXED] — §ISO/IEC 19775-1, 5.3.7, 5.3.9-5.3.12: Canonical XML retains MFImage and all four MFMatrix value types.
- **PROTO-EMPTY-OVERRIDE-WRITE** [major/FIXED] — §ISO/IEC 19775-1, 4.8; ISO/IEC 19776-1, 4.3.10: JSON and Classic writers retain explicit NULL and empty MFNode prototype overrides.
- **SCRIPT-FIELD-TYPE-OBJECTS** [major/FIXED] — §29.2.4; ISO/IEC 19777-1 clause 7 (field objects): The ECMAScript binding had no field-type objects: `new SFVec3f(1, 2, 3)` raised a ReferenceError, and a received vector had no methods or index access, so typical authored scripts failed at their first line.
  - runtime/script/FieldTypesPrelude.hpp (ES5.1, evaluated by both backends at load) defines SFVec2f/2d/3f/3d/4f/4d, SFColor, SFColorRGBA, SFRotation, SFImage and all MF* constructors with the binding's methods and index accessors; MF values are JS arrays. Pushed values adopt the same prototypes from a table scripts cannot replace. SFRotation.multiply applies the receiver first (Open Inventor / X_ITE convention; the standard's text is ambiguous). Not covered: SFMatrix3f/4f methods and VrmlMatrix (matrices stay flat arrays), SFNode/MFNode construction from a string. Tests: ecmascript/quickjs backend "field types" cases.
- **SCRIPT-SFNODE-FIELD-ACCESS** [major/FIXED] — §29.2.6, 29.4.1; ISO/IEC 19777-1 clause 7 (SFNode object): A script's SFNode was an opaque handle with no properties, so a directOutput script could not read or write another node's fields from ECMAScript at all; only Browser.addRoute could use the handle.
  - Node handles expose fields as properties in both backends (Duktape Proxy, QuickJS exotic hooks), routed through SaiContext::getField/setField, so the directOutput gate and ADR-0029 write semantics apply. set_/_changed aliases accepted. Unknown names read as undefined; writes to unknown or non-input fields throw. Not covered: the SFNode methods (getNodeName, getNodeType, getFieldDefinitions, toVRMLString, toXMLString). Tests: ecmascript/quickjs backend "node fields" cases.
- **SCR-005** [minor/CLOSED] — §29.3.1: autoRefresh/autoRefreshTimeLimit URL reload + re-initialize() absent.
  - Closed 2026-09-26: ScriptSystem::update() runs runAutoRefresh per tick — a loaded Script with autoRefresh>0 re-fetches and re-initializes on the interval (shutdown -> resolve+load -> initialize), stopping once autoRefreshTimeLimit (measured from the load that opened the refresh window; 0 = no limit) elapses. Tested in x3d_script_system (testAutoRefresh).
- **SCR-007** [minor/FIXED] — §29.2.2, 19777-1: SFImage + MFImage + MFMatrix3f/3d/4f/4d marshal to/from ECMAScript (previously fell through to undefined/empty in pushValue/toValue). SFImage uses the spec-canonical {x, y, comp, array} JS shape with high-byte-first packed pixels (mirrors the FieldValueIO fmtImage/parseImage packing).
- **ENC-CDATA-SCRIPT** [minor/FIXED `1e3c51d`] — §ISO 19776-1 (CDATA); 19775-1 29: Script source containing the literal `]]>` is silently truncated (`if (a]]>b)` -> `if (ab)`) — the XML writer wraps source in one CDATA block without splitting.
  - codec_string_hardening_test.cpp: XML writing splits embedded CDATA terminators without changing Script source.
- **SCRIPT-SAI-ADDROUTE-VALIDATE** [minor/FIXED] — §ISO/IEC 19775-2 (SAI addRoute: INVALID_NODE / INVALID_FIELD); 19775-1 4.4.2.2, 4.3.7: Browser.addRoute accepted any endpoints — a null node, an unknown field, a non-output source, a non-input sink or mismatched types all went straight into the live route graph.
  - SaiContext::addRoute now validates with the same rules as the document-ROUTE bridge (X3DSceneBridge): non-null nodes, fields present (set_/_changed aliases resolved), source readable, sink writable, identical types. It throws std::invalid_argument, which surfaces as a JS error. deleteRoute rejects null nodes. Tests: ecmascript/quickjs backend T15d.
- **SCRIPT-OUTPUTONLY-REEMIT** [low/CLOSED] — §29.2.4 (ECMAScript binding 19777-1): An explicit same-value assignment to a Script outputOnly field is suppressed — strict X3D semantics say an explicit eventOut assignment generates an event regardless of value.
  - EcmaScriptBackend.cpp readbackAuthorGlobals diffed the JS global against the stored value and skipped if equal, for BOTH inputOutput (correct) and outputOnly (a re-assert on two ticks fired once). Closed 2026-09-26: the no-op diff suppression now applies to inputOutput only, in both backends (runtime/script/EcmaScriptBackend.cpp, runtime/script/QuickJsBackend.cpp); an outputOnly re-assignment always emits. Tested in x3d_ecmascript_backend (T18).
